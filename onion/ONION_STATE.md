# Onion — Master State Document

**Canonical product name:** Onion  
**Previous working names:** Consulting Operations Hub, OneHorn  
**Owner:** Uday Teki  
**Business:** Standalone consulting and advisory practice  
**Current phase:** Private pilot / pre-production  
**Validation target:** 3–10 real consulting engagements before major productization decisions

---

## 1. Product Purpose

Onion is the private operating system for Uday's consulting practice.

It supports:
- client transformation engagements;
- technology / GCC provider advisory;
- commercial workflow;
- delivery;
- evidence;
- finance;
- growth;
- knowledge;
- governed AI agents.

The primary objective is to help the consulting team:

**acquire → diagnose → decide → contract → deliver → measure → close → learn**

with stronger repeatability, evidence, human accountability, and AI leverage.

---

## 2. Standalone Boundary

Onion must remain completely separate from:
- Assemble Teams
- GameChangers
- their repositories
- their deployments
- their branding
- their customer/product data
- their secrets
- their analytics
- their product roadmaps

The historical name `OneHorn` must not cause Onion to be linked to any existing Assemble Teams `OneHorn` repository.

### Repository hosting exception — approved 2026-10-03
Uday explicitly approved `Assemble-Teams/CuriousPI` as the bootstrap GitHub host for Onion. Onion must be isolated under a dedicated branch and `/onion` namespace. This exception applies to source hosting only and does not authorize cross-project branding, client data, analytics, secrets, product data, or production runtime coupling. The long-term repository decision remains subject to Cursor/RAS audit.

## 5. Current Product Strategy

**private-first + Google-first + evidence-first + pilot-first**

Google Workspace remains the preferred low-cost operating environment where appropriate.

Custom software should be built only when:
1. it materially improves consulting acquisition/delivery/measurement;
2. the need appears in real work;
3. Google Workspace is insufficient;
4. confidentiality and human authority are preserved;
5. RAS can verify it.

## 8. Agent Governance

Autonomy levels:
- A0 Advisory
- A1 Read
- A2 Propose
- A3 Internal Operator
- A4 Approval-Gated Executor

No unrestricted autonomy in the pilot.

Consequential actions require human approval.

Permissions must be enforced in code/runtime rather than prompt text alone.

---

## 9. Built / Wired / Proven

Permanent reporting standard:

- **Built** — code/config/artifact exists
- **Wired** — connected to the real intended workflow/dependency
- **Proven** — passed representative acceptance testing

Never use a generic "done" where these states differ.

## 11. Deferred Scope

Deferred unless explicitly approved:
- public SaaS signup
- public Paperclip
- broad external client/provider portal
- heavy CRM replacement
- large microservice architecture
- WhatsApp / Messenger
- dozens of permanent agents
- complex SaaS billing
- speculative benchmark platform
- major paid SaaS additions
- productization before pilot evidence

## 13. Launch Gates

Production remains blocked until evidence exists for:
- standalone repository
- standalone deployment
- authentication
- authorization
- secure shared persistence
- client/provider isolation
- Google integration
- end-to-end intake
- privacy retention/deletion
- abuse protection
- tested backup/restore
- operational alerting
- commercial lifecycle
- onboarding/offboarding
- browser/mobile QA
- accessibility baseline

---

## 14. Canonical Success Principle

Onion succeeds when it increases the quality, repeatability, safety, evidence discipline, and leverage of the consulting organization.

The number of agents and features is not the success metric.
